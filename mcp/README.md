# Maister-Tracker MCP Worker (read-only tools)

Отдельный Cloudflare Worker для чтения данных «Майстер-Трекера» через MCP и
AI-ответов `/ask`. MCP tools не создают, не редактируют и не удаляют заявки.
Это **не** означает, что Worker ничего не записывает: он может обновлять KV-кэш,
а PWA передаёт ему проекцию AddressBook через `/directory`.

## Источники данных и хранение

- **Заявки и смены:** Google Sheets через существующий подписанный GAS sync
  contract остаётся source of truth. Worker использует подписанные GET actions
  `list` и `getTicketById`; KV не заменяет Sheets и не принимает изменения заявок.
- **Опциональный `MT_SNAPSHOT_KV`:** ключ `mt:snapshot:v4`
  (`SNAPSHOT_VERSION = 4`) хранит версионированную **редактированную проекцию
  клиентских и рабочих данных**: заявки, смены, внутренний адресный поисковый
  индекс и время сохранения. Это не анонимные данные: видимые поля включают
  `clientName`, `phone`, `address` и другие рабочие сведения. Доступ к KV должен
  защищаться как доступ к персональным данным.
- **Граница redaction:** перед записью snapshot строки GAS преобразуются
  whitelist-мапперами. Сырые строки, `backupNote`, `fullDataJson`, `password`,
  `login`, приватный `masterNote`, фото, токены и секреты в проекцию не входят.
  Внутренний поисковый индекс строится из допустимого текста заявки и исключает
  приватные маркеры из `backupNote` и приватную заметку мастера. `get_ticket`
  читает отдельную заявку через GAS и применяет тот же whitelist.
- **AddressBook:** PWA передаёт отдельно города и улицы (`id`, `cityId` для
  улиц, `name`, `aliases`, `active`, `updatedAt`). Они хранятся в том же KV под
  другим ключом `mt:directory:v1`, без заявок, клиентов и телефонов. Это
  проекция локального справочника телефона, а не копия Sheets. Записи
  объединяются по UUID; для одного UUID побеждает более новый `updatedAt`,
  архивирование обозначается `active:false`, автоматического удаления нет.
  Названия и aliases — реальные адресные данные, не «анонимные».

### Поведение snapshot-кэша

При наличии корректной KV-копии fresh (по умолчанию до 5 минут) запросы списка
обслуживаются из неё. Stale-копия (по умолчанию до 24 часов) отдаётся сразу,
а обновление из GAS запускается в фоне. При cold miss Worker читает GAS и после
успешного ответа сохраняет проекцию. Если GAS недоступен, но копия существует,
возвращается последняя рабочая копия, в том числе старше stale-окна. Без KV
binding либо при ошибке чтения/записи KV Worker продолжает прямое чтение GAS;
ошибка KV сама по себе не должна блокировать ответ. Опциональный Cron Trigger
вызывает `scheduled()` для прогрева snapshot. Старые snapshot-ключи не
переписываются при смене версии схемы.

## Маршруты

| Маршрут | Поведение |
|---|---|
| `POST /mcp` | Stateless JSON-RPC 2.0 / Streamable HTTP, Bearer auth; read-only MCP tools. |
| `GET /mcp` | `405`: SSE-поток не предоставляется. |
| `GET /healthz` | Публичная проверка доступности без рабочих данных. |
| `GET /ai/config` | Публичное описание доступности AI-провайдеров без ключей. |
| `POST /ask` | AI-оркестратор (DeepSeek или Groq, если настроен): модель выбирает разрешённые read tools, Worker выполняет их сам. |
| `POST /directory` | Принимает AddressBook-проекцию от PWA с Bearer auth; без KV отвечает `503`. |

`OPTIONS` preflight и CORS доступны для `/healthz`, `/ai/config`, `/ask` и
`/directory`; `/mcp` остаётся без browser CORS. Ответы с данными имеют
`Cache-Control: no-store`. Cron — scheduled handler, а не HTTP endpoint.

## Доступ и безопасность

`MCP_BEARER_TOKENS` задаёт scoped токены `name:token:read` для `/mcp`.
`ASK_BEARER_TOKENS`, если задан, используется для `/ask` и `/directory`;
иначе они принимают MCP-токены. Сейчас поддержан только scope `read`:
он ограничивает MCP tools, но `/directory` выполняет отдельную запись
справочника после той же аутентификации. Токены сравниваются по SHA-256
дайджестам с константным временем сравнения и не возвращаются клиенту.
Лимит запросов на токен задаётся `MCP_RATE_LIMIT_PER_MIN` (по умолчанию
120/мин); превышение возвращает `429` с `Retry-After`. Неверная обязательная
конфигурация отключает защищённые data endpoints, а не открывает доступ.

`GAS_SYNC_URL`, `GAS_SYNC_HMAC_SECRET`, `MCP_BEARER_TOKENS`, а также
настроенные `ASK_BEARER_TOKENS`, `DEEPSEEK_API_KEY`, `GROQ_API_KEY` должны
задаваться через secrets/env; не помещайте их в репозиторий или KV. OAuth
resource-server слой здесь не реализован. KV-снимок защищён redaction, но
**не обезличен**: наличие Bearer auth и whitelist не делает рабочие данные
публичными.

### Что получают клиенты

Заявки доступны только через whitelist-проекцию: в частности, id/дата/тип,
адрес и UUID привязки, клиент и телефон, оплата и суммы, разрешённые заметки,
материалы и работы. Не выдаются `password`, `login`, приватный `masterNote`,
служебные `tg*` поля, `syncHmacSecret`, токены, сырые `backupNote` и
`fullDataJson`, фото и неизвестные поля исходных строк. Смены также проходят
отдельный whitelist-маппер. Redaction проверяется unit/integration/security
тестами, включая данные с приватными маркерами.

## MCP tools

Все зарегистрированные tools имеют `readOnlyHint:true` и
`destructiveHint:false`:

| Tool | Назначение |
|---|---|
| `list_tickets` | Список заявок с фильтрами, пагинацией. |
| `get_ticket` | Одна заявка по `ticket_id`. |
| `search_tickets` | Текстовый поиск по допустимым полям заявки. |
| `query_tickets` | Структурированный поиск, подсчёт, группировки и статистика. |
| `list_catalog` | Названия материалов, работ, городов, тегов и напарников из заявок. |
| `find_tickets_by_address` | Поиск заявок по адресу с directory UUID, когда справочник доступен. |
| `list_places` | **TICKETS:** адреса, на которых есть заявки; не полный справочник. |
| `list_directory` | **DIRECTORY:** города/улицы AddressBook независимо от наличия заявок; при отсутствии проекции сообщает `available:false`. |
| `get_tickets_by_date` | Заявки за дату. |
| `get_shifts` | Смены за период/напарника. |
| `get_reports` | Поденные финансовые сводки. |
| `get_statistics` | Агрегаты за день, неделю, месяц или всё время. |

## Код и проверки

Основные границы: `src/index.js` — маршрутизация/auth; `src/data/snapshot.js`
— KV-кэш; `src/data/directory.js` — проекция AddressBook; `src/gas/` —
подписанный GAS-клиент и redaction; `src/tools/` — схемы и read tools;
`src/ask/` — AI-оркестрация. `wrangler.example.toml` — пример опционального KV
binding и cron, `wrangler.dev.toml` — dev-конфигурация. Production-секреты
не должны находиться в этих файлах.

```bash
cd mcp
npm test
npm run check
```

Тесты покрывают unit, integration, security и паритет с модулями PWA и
векторами HMAC-контракта. `npm run check` запускает Bash-скрипт проверки
синтаксиса JS; в Windows ему нужен Bash (например, Git Bash).

## Возможное развитие (не реализовано)

Запись заявок через MCP, подтверждение удаления, audit UI и OAuth 2.1
требуют отдельного проектирования и не входят в текущие read-only tools.
