## Money protection and conflicts

The effective view copies exactly work_type, work_category and onu_used.
Every other value comes from the current _DispatcherData row, including
total, amount, payment fields, fees, tariffs, onu_replacement and materials.
Canonical rows, their source_version/hash, receipts and outbox are not rewritten.
The append-only _DispatcherOnuCorrections journal stores the version/hash,
BEFORE evidence, three-field target and request identity.

Relevant evidence includes date/time, type/category, ONU counters/MAC, material
identities/quantities, work descriptions and dispatcher comment. Prices in
material JSON/display and work display are excluded from the evidence fence.
Ordinary financial updates therefore retain the correction while rendering
current money. Changes to the guarded evidence produce CONFLICT in preview
and ONU_CORRECTION_SOURCE_CONFLICT in diagnostics. Rendering stops before
clearing the visible report, so its prior view may be stale until reviewed or
rolled back. Normal source synchronization still commits its own data/ACK.
No conflict is automatically reapproved.

This fence covers evidence available in dispatcher DTOs; it cannot observe
canonical fields not transported to GAS. Fresh comparison with primary Заявки,
including onuAccountingVersion/equipment and customer ownership, is an
execution prerequisite. It is not replaced by a source hash or MAC.

Cached and durable correction request replays recheck current evidence and
return current money. An apply superseded by rollback, or an old rollback
superseded by a newer apply, returns ONU_CORRECTION_SUPERSEDED. Old snapshots
without the evidence fence fail closed. Rollback appends a tombstone, removes
the overlay and renders current source values; it never restores old finances.
If rendering fails after journal append, retry the same request ID/payload:
the journal prevents a second apply and rendering can finish. Stop before the
next ID after any error. A prepared dispatcher receipt blocks a new correction.
