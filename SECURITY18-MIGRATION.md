# Майстер-Трекер — security.18 HMAC migration

Цей файл — контрольний порядок переходу, щоб не ламати робочу Google-синхронізацію.

## До переходу

- Поточна контрольна PWA: `v65.0-security.17.3`.
- `js/security-sync-hmac-v65-18.js` підготовлений, але не підключений у Service Worker.
- `apps-script-security-v65-18-patch.gs` підготовлений, але не задеплоєний користувачем.
- `shiftsScriptUrl` не мігруємо цим протоколом: HMAC стосується лише основного Apps Script заявок.
- Зробити фізичну копію/backup перед зміною Apps Script.

## Крок 1 — новий секрет

Використати новий випадковий секрет довжиною щонайменше 32 символи. Не комітити реальний секрет у GitHub.

Один і той самий новий секрет тимчасово має бути:
- у `SYNC_SECRET` фактичного Apps Script deployment;
- у налаштуванні Google Sync застосунку на пристрої.

## Крок 2 — Apps Script migration wrapper

У фактичному `Code.gs` перейменувати лише дві старі точки входу:

- `function doPost(e)` → `function legacyDoPostV65(e)`
- `function doGet(e)` → `function legacyDoGetV65(e)`

Після цього додати в кінець `apps-script-security-v65-18-patch.gs` і створити нову версію Web App deployment.

На цьому етапі legacy `?secret=` fallback ще працює, тому стара PWA не повинна відвалитися під час переходу.

## Крок 3 — обов'язковий тест ДО включення клієнта

На ще старій PWA `17.3` перевірити хоча б одну операцію читання/запису. Якщо стара PWA після серверного deployment перестала синхронізуватися — security.18 клієнт НЕ вмикати; виправити сервер спочатку.

## Крок 4 — увімкнення HMAC клієнта

Тільки після кроку 3 додати `js/security-sync-hmac-v65-18.js` до `CORE_ASSETS` та `injectSecurityLayer()` у `sw.js`, підняти cache/release на security.18.

## Крок 5 — smoke test security.18

Послідовно перевірити:

1. завантаження заявок із Google;
2. створення нової тестової заявки;
3. перевірку, що вона реально з'явилась у таблиці;
4. редагування цієї заявки;
5. перевірку фактичного оновлення рядка;
6. видалення тестової заявки;
7. перевірку фактичного видалення;
8. перезапуск PWA і повторне читання;
9. фото/Telegram не повинні змінитися;
10. синхронізацію змін перевірити окремо — вона лишається на старому `shiftsScriptUrl` протоколі.

## Крок 6 — strict cutover

Лише після успішного smoke test замінити HMAC wrapper `doPost/doGet` на функції з `apps-script-security-v65-18-strict-patch.gs` і задеплоїти нову версію Apps Script.

Після strict cutover запити зі старим `?secret=` або `secret` у JSON без валідного HMAC більше не приймаються.

## Відкат

Якщо security.18 клієнт дає регрес:

- повернути Service Worker cache/список модулів до останнього стабільного `17.3`;
- серверний migration wrapper може тимчасово лишитися, бо до strict cutover він підтримує старий `secret`;
- якщо проблема саме в серверному wrapper — повернути попередню версію Apps Script deployment.

Не робити `clearAll`/масову синхронізацію під час діагностики міграції.
